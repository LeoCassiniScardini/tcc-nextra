# «Containment»

A relação «Containment» representa uma relação entre um recipiente e o seu conteúdo, sendo esse conteúdo uma «Quantity», isto é, uma quantidade de matéria ou substância.

## Exemplos simples:

- Barril -- «Containment» -- Cerveja
- Garrafa -- «Containment» -- Água
- Tanque -- «Containment» -- Combustível
- Frasco -- «Containment» -- Medicamento Líquido
- Saco -- «Containment» -- Areia

A documentação da OntoUML define «Containment» como uma relação entre um container e seu conteúdo, sendo o conteúdo uma «Quantity», por exemplo, um barril que contém cerveja.

## Definição

A relação «Containment» deve ser usada quando uma entidade funciona como recipiente de uma quantidade de matéria.

### Exemplo:

```
«Kind» Garrafa
«Quantity» Água

Garrafa -- «Containment» -- Água
```

- Nesse caso, a garrafa é o recipiente, e a água é o conteúdo.

### Outro exemplo:

```
«Kind» Tanque
«Quantity» Combustível

Tanque -- «Containment» -- Combustível
```

- O tanque contém uma quantidade de combustível.

## Diferença entre Containment e SubQuantityOf

As duas relações envolvem quantidades, mas possuem sentidos diferentes.

### Containment

Usado quando há um recipiente contendo uma quantidade.

```
Garrafa -- «Containment» -- Água
```

- A garrafa não é uma subquantidade da água, nem a água é componente funcional da garrafa. A garrafa apenas contém a água.

### SubQuantityOf

Usado quando uma quantidade é parte de outra quantidade.

```
Álcool -- «SubQuantityOf» -- Vinho
```

- O álcool é uma subquantidade do vinho. Aqui não há necessariamente um recipiente.

A documentação da OntoUML associa Containment e SubQuantityOf ao grupo de relações parte-todo envolvendo Quantity.

## Diferença entre Containment, ComponentOf e MemberOf

### Containment

Recipiente contém uma quantidade.

```
Saco -- «Containment» -- Areia
```

### ComponentOf

Parte funcional compõe um todo funcional.

```
Motor -- «ComponentOf» -- Carro
```

### MemberOf

Indivíduo é membro de um coletivo.

```
Aluno -- «MemberOf» -- Turma
```

A diferença principal é:

- **Containment** = recipiente → quantidade
- **ComponentOf** = componente funcional → todo funcional
- **MemberOf** = indivíduo → coletivo
- **SubQuantityOf** = quantidade → quantidade

## Restrições

A relação «Containment» deve ter como conteúdo uma «Quantity». Ou seja, o elemento contido deve representar uma quantidade de matéria ou substância.

### Exemplo correto:

```
«Kind» Barril
«Quantity» Cerveja

Barril -- «Containment» -- Cerveja
```

### Exemplo inadequado:

```
Sala -- «Containment» -- Aluno
```

Aluno não é uma quantidade de matéria. Se a ideia for representar que o aluno está em uma sala, talvez seja melhor usar uma relação situacional, espacial ou contextual, conforme o objetivo do modelo.

### Outro exemplo inadequado:

```
Turma -- «Containment» -- Aluno
```

Se a turma for um coletivo de alunos, o correto é:

```
Aluno -- «MemberOf» -- Turma
```

## Multiplicidade

A documentação indica que as multiplicidades da relação «Containment» devem ser exatamente 1..1, pelo mesmo motivo aplicado à relação «SubQuantityOf».

Isso significa que uma instância específica de conteúdo deve estar associada a um recipiente específico naquela relação de contenção.

### Exemplo:

```
Garrafa específica A -- contém -- Porção específica de Água A
```

- Aquela porção específica de água está naquele recipiente específico.

## Questões comuns

### Quando devo usar Containment?

Use quando houver uma relação clara de recipiente e conteúdo material.

**Exemplos:**

- garrafa contém água
- barril contém cerveja
- tanque contém combustível
- frasco contém remédio líquido
- saco contém areia
- caixa contém grãos

### Posso usar Containment para pessoas dentro de uma sala?

Em regra, não é o uso típico da relação em OntoUML. Containment é definida para conteúdo do tipo «Quantity», como água, areia, combustível ou cerveja.

Para pessoas em uma sala, normalmente seria mais adequado modelar uma relação espacial, uma situação ou um evento, conforme o domínio:

```
«Situation» Pessoa em Sala
```

ou, se for um evento:

```
«Event» Permanência em Sala
```

### Qual é a diferença entre conter água e ter água como parte?

Se o foco for o recipiente, use «Containment»:

```
Garrafa -- «Containment» -- Água
```

Se o foco for uma quantidade dentro de outra quantidade, use «SubQuantityOf»:

```
Álcool -- «SubQuantityOf» -- Vinho
```

### O recipiente precisa ser Kind?

Normalmente o recipiente será uma entidade independente, como Garrafa, Barril, Tanque, Frasco ou Saco, frequentemente modelada como «Kind». O conteúdo, por sua vez, deve ser uma «Quantity».

## Exemplos

### Exemplo 1 — Garrafa de água
```
«Kind» Garrafa
«Quantity» Água

Garrafa -- «Containment» -- Água
```

- A garrafa é o recipiente.
- A água é a quantidade contida.

### Exemplo 2 — Barril de cerveja
```
«Kind» Barril
«Quantity» Cerveja

Barril -- «Containment» -- Cerveja
```

- A cerveja é uma quantidade de substância contida no barril.

### Exemplo 3 — Tanque de combustível
```
«Kind» Tanque
«Quantity» Combustível

Tanque -- «Containment» -- Combustível
```

- O tanque contém uma quantidade de combustível.

### Exemplo 4 — Medicamento líquido
```
«Kind» Frasco
«Quantity» Medicamento Líquido

Frasco -- «Containment» -- Medicamento Líquido
```

- O medicamento líquido é uma quantidade contida no frasco.

## Resumo final

A relação «Containment» deve ser usada para representar uma relação entre um recipiente e uma quantidade de matéria contida. Ela é adequada para exemplos como Garrafa–Água, Barril–Cerveja, Tanque–Combustível, Frasco–Medicamento Líquido e Saco–Areia. Não deve ser usada para membros de coletivos, como Aluno–Turma, nem para componentes funcionais, como Motor–Carro.
