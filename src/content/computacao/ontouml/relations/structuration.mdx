# «Structuration»

A relação «Structuration» conecta uma qualidade a uma estrutura de valor que organiza ou define seus possíveis valores.

Ela é usada principalmente quando um «Quality» precisa ser associado a um espaço de valores, escala, unidade, medida, padrão ou domínio estruturado.

## Exemplos simples:

- Peso -- «Structuration» -- Quilograma
- Temperatura -- «Structuration» -- Escala Celsius
- Preço -- «Structuration» -- Valor Monetário
- Cor -- «Structuration» -- Espaço de Cor
- Nota Escolar -- «Structuration» -- Escala de Nota

Em termos práticos:

- «Quality» representa a propriedade
- «Structuration» liga essa propriedade ao seu espaço de valores

## Categorias principais

| Propriedade | Valor |
|---|---|
| Categoria | Relação de estruturação |
| Origem típica | Quality |
| Destino típico | Estrutura de valor / espaço de qualidade |
| Relação relacionada | Characterization |
| Função principal | Indicar como uma qualidade é estruturada |
| Exemplo típico | Peso estruturado em quilogramas |
| Uso comum | Medidas, escalas, unidades, valores monetários, cores, notas |

## Definição

Uma relação «Structuration» deve ser usada quando a qualidade de um indivíduo precisa ser relacionada a uma estrutura que permite interpretar seu valor.

### Exemplo:

```
«Kind» Pessoa
«Quality» Peso
«Quality» Altura

Pessoa -- «Characterization» -- Peso
Pessoa -- «Characterization» -- Altura

Peso -- «Structuration» -- Quilograma
Altura -- «Structuration» -- Metro
```

Nesse exemplo:

- Pessoa é o portador;
- Peso e Altura são qualidades da pessoa;
- Quilograma e Metro estruturam os valores dessas qualidades.

## Relação com «Quality»

A «Structuration» é especialmente importante para «Quality», porque a qualidade normalmente possui um valor em algum domínio.

### Exemplo:

```
«Quality» Temperatura Corporal
Temperatura Corporal -- «Structuration» -- Escala Celsius
```

A temperatura corporal pode ter valores como:

- 36,5 °C
- 37,0 °C
- 38,5 °C

Esses valores só fazem sentido porque existe uma escala estruturante.

## Relação com «Characterization»

A «Characterization» liga o portador à qualidade.

A «Structuration» liga a qualidade ao seu espaço de valor.

### Exemplo completo:

```
«Kind» Produto
«Quality» Preço
«Kind» Valor Monetário

Produto -- «Characterization» -- Preço
Preço -- «Structuration» -- Valor Monetário
```

Nesse caso:

- Produto possui um Preço
- Preço é estruturado por Valor Monetário

## Restrições

A relação «Structuration» deve ser usada apenas quando o elemento estruturado for uma qualidade ou algo equivalente a uma propriedade cujo valor precisa de estrutura.

### Exemplo correto:

```
«Quality» Peso
Peso -- «Structuration» -- Unidade de Massa
```

### Exemplo correto:

```
«Quality» Cor
Cor -- «Structuration» -- Espaço RGB
```

### Exemplo inadequado:

```
Pessoa -- «Structuration» -- Contrato
```

Pessoa não é uma qualidade e Contrato não é estrutura de valor. Se a intenção for representar uma relação jurídica, provavelmente será necessário usar «Relator», «Mediation» e «Material».

### Outro exemplo inadequado:

```
Contrato -- «Structuration» -- Pessoa
```

Um contrato não é uma qualidade estruturada por pessoa. Contrato normalmente é um «Relator».

## Questões comuns

### Qual é a diferença entre Characterization e Structuration?

- A «Characterization» liga o portador à sua qualidade.
  ```
  Pessoa -- «Characterization» -- Peso
  ```

- A «Structuration» liga a qualidade ao domínio que estrutura seu valor.
  ```
  Peso -- «Structuration» -- Quilograma
  ```

### Quando devo usar Structuration?

Use quando a qualidade precisa de uma escala, unidade ou domínio de valores.

**Exemplos:**

- Peso → Quilograma
- Altura → Metro
- Temperatura → Celsius
- Preço → Real
- Nota → Escala de 0 a 10
- Cor → RGB
- Pressão Arterial → mmHg

### Toda Quality precisa de Structuration?

Nem sempre é obrigatório representar explicitamente, mas é recomendado quando o valor da qualidade é relevante para o domínio.

**Exemplo simples, sem estrutura explícita:**

```
Pessoa -- «Characterization» -- Idade
```

**Exemplo mais completo:**

```
Pessoa -- «Characterization» -- Idade
Idade -- «Structuration» -- Anos
```

### Posso usar Structuration com Mode?

Em regra, não é o uso principal.
O «Mode» representa uma propriedade intrínseca sem valor estruturado formal. Quando a propriedade precisa ser estruturada por escala, medida ou domínio de valores, normalmente ela deve ser modelada como «Quality».

**Exemplo:**

```
«Mode» Dor
```

Se o foco for apenas a existência da dor, Mode pode bastar.

Mas, se for necessário representar intensidade da dor em escala de 0 a 10, pode-se modelar:

```
«Quality» Intensidade da Dor
Intensidade da Dor -- «Structuration» -- Escala de Dor 0 a 10
```

## Exemplos

### Exemplo 1 — Pessoa
```
«Kind» Pessoa
«Quality» Peso
«Quality» Altura
«Quality» Idade

Pessoa -- «Characterization» -- Peso
Pessoa -- «Characterization» -- Altura
Pessoa -- «Characterization» -- Idade

Peso -- «Structuration» -- Quilograma
Altura -- «Structuration» -- Metro
Idade -- «Structuration» -- Ano
```

- A pessoa é caracterizada por qualidades.
- Cada qualidade pode ser estruturada por uma unidade ou escala.

### Exemplo 2 — Produto
```
«Kind» Produto
«Quality» Preço
«Quality» Peso
«Quality» Data de Validade

Produto -- «Characterization» -- Preço
Produto -- «Characterization» -- Peso
Produto -- «Characterization» -- Data de Validade

Preço -- «Structuration» -- Valor Monetário
Peso -- «Structuration» -- Unidade de Massa
Data de Validade -- «Structuration» -- Calendário
```

- O preço, o peso e a validade são qualidades do produto, e cada uma possui uma estrutura de valor própria.

### Exemplo 3 — Saúde
```
«Kind» Pessoa
«Quality» Temperatura Corporal
«Quality» Pressão Arterial
«Quality» Frequência Cardíaca

Pessoa -- «Characterization» -- Temperatura Corporal
Pessoa -- «Characterization» -- Pressão Arterial
Pessoa -- «Characterization» -- Frequência Cardíaca

Temperatura Corporal -- «Structuration» -- Escala Celsius
Pressão Arterial -- «Structuration» -- mmHg
Frequência Cardíaca -- «Structuration» -- Batimentos por Minuto
```

- As qualidades de saúde precisam de escalas ou unidades para que seus valores sejam compreendidos.

### Exemplo 4 — Direito previdenciário
```
«Relator» Benefício Previdenciário
«Quality» Valor do Benefício
«Quality» Data de Início do Benefício
«Quality» Número do Benefício

Benefício Previdenciário -- «Characterization» -- Valor do Benefício
Benefício Previdenciário -- «Characterization» -- Data de Início do Benefício
Benefício Previdenciário -- «Characterization» -- Número do Benefício

Valor do Benefício -- «Structuration» -- Real Brasileiro
Data de Início do Benefício -- «Structuration» -- Calendário
Número do Benefício -- «Structuration» -- Padrão Numérico do INSS
```

- O benefício previdenciário é caracterizado por qualidades, e essas qualidades possuem estruturas próprias de interpretação.

## Resumo final

A relação «Structuration» deve ser usada para ligar uma qualidade ao seu espaço de valores, escala, unidade ou estrutura de interpretação. Ela complementa a «Characterization»: enquanto Characterization mostra que uma entidade possui uma qualidade, Structuration mostra como essa qualidade é medida, organizada ou interpretada.
