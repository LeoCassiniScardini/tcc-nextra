# «Characterization»

A relação «Characterization» conecta um portador a uma propriedade intrínseca que o caracteriza. Essa propriedade pode ser um «Mode» ou um «Quality».

## Exemplos simples:

- Pessoa -- «Characterization» -- Peso
- Pessoa -- «Characterization» -- Dor
- Produto -- «Characterization» -- Preço
- Veículo -- «Characterization» -- Cor
- Benefício Previdenciário -- «Characterization» -- Valor do Benefício

A documentação da OntoUML define «Characterization» como uma relação entre um tipo portador e sua característica intrínseca. Essa característica é existencialmente dependente do portador e pode ser estereotipada como «Quality» ou «Mode».

## Categorias principais

| Propriedade | Valor |
|---|---|
| Categoria | Relação formal / relação de inerência |
| Direcionada | Sim |
| Origem | Portador da propriedade |
| Destino permitido | Quality, Mode |
| Multiplicidade da origem | 1..1 |
| Multiplicidade do destino | 1..* |
| Relação típica | Portador → característica intrínseca |
| Exemplos | Pessoa–Peso, Pessoa–Dor, Produto–Preço |
| Propriedades binárias | Não reflexiva, não transitiva, não simétrica e não cíclica |

## Definição

Uma relação «Characterization» deve ser usada quando uma entidade possui uma característica que não existe sozinha, mas apenas como característica de algum portador.

### Exemplo:

```
«Kind» Pessoa
«Quality» Peso

Pessoa -- «Characterization» -- Peso
```

O Peso não existe de forma independente. Ele é sempre o peso de alguma pessoa, animal, objeto ou entidade física.

### Outro exemplo:

```
«Kind» Pessoa
«Mode» Dor

Pessoa -- «Characterization» -- Dor
```

A Dor também não existe isoladamente. Ela existe como dor de uma pessoa ou de outro ser capaz de senti-la.

## Restrições

A relação «Characterization» deve ter como destino um «Quality» ou um «Mode». Isso ocorre porque ela serve justamente para ligar o portador a uma propriedade intrínseca.

### Exemplo correto:

```
«Kind» Pessoa
«Quality» Altura

Pessoa -- «Characterization» -- Altura
```

### Exemplo correto:

```
«Kind» Pessoa
«Mode» Habilidade

Pessoa -- «Characterization» -- Habilidade
```

### Exemplo inadequado:

```
Pessoa -- «Characterization» -- Contrato
```

Contrato não é uma propriedade intrínseca da pessoa. Normalmente, contrato seria modelado como «Relator».

### Exemplo inadequado:

```
Pessoa -- «Characterization» -- Escola
```

Escola não é propriedade intrínseca da pessoa. Se a intenção for representar matrícula, o adequado seria usar um «Relator» Matrícula e relações «Mediation».

## Diferença entre Characterization, Mediation e Material

A «Characterization» liga um indivíduo às suas propriedades intrínsecas.

```
Pessoa -- «Characterization» -- Peso
Pessoa -- «Characterization» -- Dor
```

A «Mediation» liga um «Relator» aos participantes que ele conecta.

```
Pessoa -- «Mediation» -- Contrato
Empresa -- «Mediation» -- Contrato
```

A «Material» liga diretamente os participantes, mas é derivada de um relator.

```
Pessoa -- «Material» trabalha para -- Empresa
```

Portanto, Characterization é para propriedades internas; Mediation e Material são para relações entre participantes.

## Questões comuns

### Qual é a diferença entre Characterization e atributo comum?

Um atributo comum registra apenas um valor.

```
Pessoa.idade: inteiro
```

Já a «Characterization» é usada quando a propriedade é importante o suficiente para ser representada como uma classe própria.

```
«Kind» Pessoa
«Quality» Idade

Pessoa -- «Characterization» -- Idade
```

Isso é útil quando a propriedade precisa ter unidade, histórico, fases, medições, subtipos ou estrutura própria.

### Qual é a diferença entre caracterizar com Quality e com Mode?

Use «Quality» quando a propriedade tiver valor estruturado, medida, escala ou domínio de valores.

```
«Quality» Peso
«Quality» Altura
«Quality» Temperatura
«Quality» Preço
```

Use «Mode» quando a propriedade for uma característica intrínseca individualizada, mas sem necessidade de representar um espaço de valores estruturado.

```
«Mode» Dor
«Mode» Habilidade
«Mode» Intenção
«Mode» Permissão
```

### Todo objeto precisa ter Characterization?

Não. Use apenas quando a propriedade for relevante para o domínio. Muitas características simples podem ser modeladas como atributos comuns.

**Exemplo simples como atributo:**

```
Pessoa.nome: string
Pessoa.idade: inteiro
```

**Exemplo mais ontológico:**

```
«Kind» Pessoa
«Quality» Nome
«Quality» Idade

Pessoa -- «Characterization» -- Nome
Pessoa -- «Characterization» -- Idade
```

### A propriedade caracterizada depende do portador?

Sim. Mode e Quality são propriedades intrínsecas existencialmente dependentes do portador. Isso significa que uma instância de Peso, Dor, Cor ou Temperatura não existe isoladamente; ela existe como propriedade de alguma entidade.

## Exemplos

### Exemplo 1 — Pessoa
```
«Kind» Pessoa
«Quality» Altura
«Quality» Peso
«Mode» Habilidade

Pessoa -- «Characterization» -- Altura
Pessoa -- «Characterization» -- Peso
Pessoa -- «Characterization» -- Habilidade
```

- Altura e Peso são qualidades da pessoa.
- Habilidade é um modo da pessoa.

### Exemplo 2 — Produto
```
«Kind» Produto
«Quality» Preço
«Quality» Peso
«Quality» Data de Validade

Produto -- «Characterization» -- Preço
Produto -- «Characterization» -- Peso
Produto -- «Characterization» -- Data de Validade
```

- As qualidades caracterizam o produto e dependem dele para existir.

### Exemplo 3 — Saúde
```
«Kind» Pessoa
«Quality» Temperatura Corporal
«Quality» Pressão Arterial
«Mode» Sintoma

Pessoa -- «Characterization» -- Temperatura Corporal
Pessoa -- «Characterization» -- Pressão Arterial
Pessoa -- «Characterization» -- Sintoma
```

- A temperatura corporal e a pressão arterial são qualidades mensuráveis.
- O sintoma pode ser modelado como modo, quando tratado como uma característica intrínseca da pessoa.

### Exemplo 4 — Direito previdenciário
```
«Relator» Benefício Previdenciário
«Quality» Valor do Benefício
«Quality» Data de Início do Benefício
«Quality» Número do Benefício

Benefício Previdenciário -- «Characterization» -- Valor do Benefício
Benefício Previdenciário -- «Characterization» -- Data de Início do Benefício
Benefício Previdenciário -- «Characterization» -- Número do Benefício
```

- O benefício previdenciário é o portador das qualidades.
- Valor, data de início e número do benefício não existem isoladamente nesse domínio; existem como características daquele benefício.

## Resumo final

A relação «Characterization» deve ser usada para ligar um portador a uma propriedade intrínseca, normalmente um «Quality» ou um «Mode». Ela é adequada para representar relações como Pessoa–Peso, Pessoa–Dor, Produto–Preço, Veículo–Cor e Benefício Previdenciário–Valor do Benefício.
